# Learning Effectiveness Trial — Mitchell Flashcards and Club Resources

**Status: protocol prepared; student outcomes not yet recorded.**

Use this teacher protocol to check whether flashcards, readings, videos, and practical exercises produce independent understanding. A design score, complete repository, or teacher rehearsal is not evidence of student learning. Record the result as “not yet tested” until students supply evidence.

This supplements the [Pilot Protocol](Pilot_Protocol.md) and [Cohort Mastery Review Protocol](../Cohort_Mastery_Review_Protocol.md). Existing course and assessment rubrics remain authoritative; the observations below do not create another promotion score.

## 1. Set up a focused trial

For the first trial, choose three important concepts or skills and students with different starting readiness. Include all participating students in the record, including unfinished attempts.

Record the resource filename, version or commit, item IDs, cohort, dates, and the existing rubric before teaching. Give a brief unaided entry check so that students who already know the topic can be distinguished from students who improve during the trial.

Select a feasible first trial rather than attempting to validate all 16 chapters at once. Evidence from a few concepts only supports conclusions about those concepts.

## 2. Collect three kinds of evidence

| Indicator | Check | Evidence to keep |
|---|---|---|
| Independent explanation | Without the answer, notes, or AI help, explain the mechanism in the student's own words; use a diagram or trace when helpful. | Brief explanation or trace, item ID, rubric result, exact misconception, and any prompts used. |
| Transfer | Change a diagram, condition, or case; ask for a prediction and reason before revealing the result. For coding skills, require a changed task or controlled experiment. | Prediction, reasoning, attempted solution, observed result, and revision of the explanation. |
| Delayed retention | Recheck the same learning target after 7–14 days using a comparable changed item. | Actual date and interval, intervening practice, new item ID, independence, and rubric result. |

For Mitchell concepts, possible teacher-designed variations include tracing an RNN after a recurrent connection is removed, examining a reward loophole in a new setting, or identifying evidence needed to support an AI capability claim. Use private or newly prepared variants for formal checks.

Kahoot responses can help identify concepts to inspect. A leaderboard position or selected answer alone does not establish independent explanation or practical competence.

## 3. Record the attempt, support, and time

Copy the following into the [Pilot Lesson Evidence Record](Pilot_Lesson_Evidence_Record.md) or a teacher-held working copy. Use one row per student and learning target.

| Student code / target / item ID | Entry evidence | Independent explanation | Changed-task transfer | Delayed check date / result | Minutes to mastery / attempts / support | Precise difficulty / likely cause / next action |
|---|---|---|---|---|---|---|
| | | | | | | |

Use the existing rubric for results and link the evidence. Label independence explicitly:

- **Independent:** no answer, notes, hints, or AI help.
- **Supported:** record the type of support; do not count it as independent success.
- **Not assessed:** pending, absent, or no comparable task; do not treat it as a zero or a pass.

Measure task time separately from setup time. If mastery is not reached, record “not yet” plus minutes spent and attempts. Keep first-attempt results alongside retest results rather than overwriting them. Note language support separately from conceptual prompting.

Keep identifiable student records in the teacher's private records. This public repository contains blank templates and aggregate trial reports.

## 4. Diagnose the source of difficulty

| Possible cause | Evidence to seek | Next action |
|---|---|---|
| Conceptual gap | The misconception persists when the same idea is presented clearly in another form. | Use a different representation, targeted practice, and a fresh independent recheck. |
| Item wording or diagram | A student can explain the idea but a term, missing condition, or diagram prevents interpreting the item. | Revise the wording or diagram while preserving the learning target; repeat the check. |
| Scoring standard | Equivalent answers receive inconsistent judgements or the rubric omits a valid explanation. | Clarify criteria and compare scored examples; rescore affected evidence. |
| Prerequisite, language, or runtime | The student cannot access the task because of an earlier skill, language barrier, or technical problem. | Address the specific obstacle; then reassess the target skill independently. |

Treat the cause as a hypothesis until evidence distinguishes it. Student errors do not automatically prove that the student or the material is at fault.

## 5. Decide what to revise

- Explanation succeeds but transfer fails: add changed cases and prediction tasks.
- Familiar questions succeed but delayed checks fail: schedule spaced retrieval and another delayed check.
- Several students misread the same item: inspect wording and diagrams before adding more instruction.
- Practical work runs but cannot be explained or rebuilt: inspect dependence on copied code or teacher intervention.
- An attempt exceeds the available time: shorten the resource or adjust scaffolding and sequencing while preserving the target.

Class pacing and individual mastery are separate decisions. If the class moves on, retain each unresolved target in the student's remediation queue with a named task and recheck date.

## 6. Report the trial and verify the revision

Use a dated report linked to the resource version tested. Report actual counts, such as independent explanation **n/N**, transfer **n/N**, delayed assessment coverage **n/N**, and delayed success **n/number assessed**. State absences, missing evidence, and support used.

A before/after change is descriptive evidence; a small trial does not establish that a resource caused the improvement or that the whole curriculum is validated.

| Resource / version / targets | Participants / starting readiness | Explanation | Transfer | Delayed coverage / success | Time and support | Revision / new version / recheck result |
|---|---|---|---|---|---|---|

After editing, use a comparable new item and preserve results from both versions. Mark delayed evidence as pending until the actual recheck. Summarise what the students can now do, remaining gaps, and the next revision without converting a design rating into an effectiveness claim.
