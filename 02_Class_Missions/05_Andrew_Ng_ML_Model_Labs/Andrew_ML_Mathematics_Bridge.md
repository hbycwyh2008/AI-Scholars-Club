# Andrew ML Mathematics Bridge

Use this bridge across Sessions 41–43 and revisit it whenever a new model introduces unfamiliar notation.

## Translation Routine

For every model, students complete:

```text
task language
→ X / y / labels and shapes
→ prediction function / equation
→ loss or objective
→ update/model rule
→ evaluation metric
→ code
→ limitation
```

## Session 41 — Mathematical Model Language

Students translate a problem statement into:

- `X`, `y`, labels, and task family;
- scalar/vector/matrix objects and their shapes;
- parameters and predictions;
- training loss/objective versus evaluation metric;
- one equation-to-words and equation-to-code explanation.

## Session 42 — Linear Regression Mathematics

Students connect:

- weighted sums and dot products;
- slope/intercept and coefficients;
- predictions and residuals;
- squared error and mean squared error;
- coefficient changes to changes in predictions.

## Session 43 — Gradient Descent Mathematics

Students connect:

- feature scale and cost surfaces;
- derivatives as local rates of change;
- partial derivatives and the gradient;
- learning rate and update direction;
- convergence, oscillation, and divergence.

## Minimum Mathematics

Students should be able to explain and use:

- scalar, vector, matrix, row, column, shape;
- feature matrix `X`, target `y`, sample count `m`, feature count `n`;
- weighted sum / dot product;
- residual and squared error;
- mean and variance;
- derivative as local rate of change;
- gradient as a direction across multiple parameters;
- learning rate;
- probability and logarithm intuition for classification;
- Euclidean distance;
- proportions/entropy/impurity intuition;
- projection and variance direction for PCA.

## Evidence

For each new model, record:

1. symbol/shape ledger;
2. one representative hand calculation;
3. equation-to-words explanation;
4. equation-to-code translation;
5. objective vs evaluation metric distinction;
6. one parameter-change prediction before running code.

A student who can run the library call but cannot explain shapes, objective, gradient/update behaviour, or evaluation has not passed the mathematics bridge.
